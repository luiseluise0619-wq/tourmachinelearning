# FestCast 서비스 아키텍처 (대상 목표 확장판)

> "축제를 예측한다"에서 → **"축제 기획을 컨설팅한다"**로 격상.
> 예측(무엇이 일어날까) + 진단(왜) + 처방(무엇을 고칠까) + 마케팅(누구에게 어떻게).

---

## 1. 핵심 서사 (심사위원 3분 스토리)

> 지자체 담당자가 축제 기획안을 넣는다.
> FestCast는 **① 예상 방문자수·흥행도를 예보**하고,
> **② 약점을 진단**하며, **③ "이렇게 바꾸면 +N%" 처방**을 주고,
> **④ 주변 인구 데이터로 "누구에게, 어떤 채널로" 홍보할지**까지 알려준다.
> → **예산 집행 전에 객관적으로 검증**한다. (과제 9 정조준)

---

## 2. 입력 → 출력 파이프라인

```
[입력] 축제 기획안
  · 축제명 / 개최지(지역코드) / 개최 시기(일정) / 장소(실내·실외)
  · 프로그램 구성 / 규모 / 예산

        │
        ▼
[데이터 결합]  ── 4대 데이터 소스 ──────────────────────────
  · TourAPI          : 축제 메타 + 과거 유사 축제 (필수 API)
  · 관광데이터랩      : 지역·시기별 방문자수 → y(타깃) 프록시
  · 기상청 ASOS      : 개최 시기 기온·강수 → 날씨 피처
  · 주민등록 인구통계  : 주변 지역 연령대·성별 인구 → 수요·타깃

        │
        ▼
[엔진] src/scoring.py
  ① 흥행도 점수 (0~100)  = 가중합(날씨·수요·프로그램·시기)
  ② 보완 피드백 (what-if) = 약한 요인별 처방 + 예상 효과
  ③ 마케팅 추천          = 주변 인구 → 타깃 세그먼트 → 채널·메시지·프로그램

        │
        ▼
[출력] 흥행 예보 리포트 (web/ Streamlit)
  · 예상 방문자수 · 흥행도 게이지
  · 강·약점 진단 + 개선 시나리오
  · 추천 타깃 + 홍보 채널 + 프로그램 보완안
```

---

## 3. 왜 "주변 인구 연령대"가 대상급 무기인가

인구 데이터 하나로 **수요 예측**과 **마케팅 전략**이 동시에 풀린다:

| 인구 데이터에서 나오는 것 | 활용 |
|---------------------------|------|
| 반경 내 총 인구 규모 | 수요(방문자수) 베이스라인 |
| 우세 연령대·성별 세그먼트 | 홍보 타깃 확정 |
| 세그먼트 특성 | 채널(인스타/현수막/맘카페 등)·메시지 톤 추천 |
| 세그먼트 ↔ 프로그램 적합도 | 프로그램 보완 처방 |

> 논리 한 줄: **인구 → 타깃 → 채널·프로그램**. 감이 아니라 데이터로 홍보 전략을 방어한다.

---

## 3-1. 내국인/외국인 분리 예측 + K콘텐츠 효과 (관광공사 정조준)

주최가 **한국관광공사**라는 점이 핵심 힌트다. 관광공사의 최대 미션은 **방한 외국인 유치**.
따라서 방문자를 **내국인 / 외국인으로 분리**해 예보하고, 특히
**"K콘텐츠 연계 시 외국인이 얼마나 더 오는가"**를 정량 비교한다.

```
외국인 방문 = 총 방문 × 외국인 기본비율 × 접근성(공항·KTX) × K콘텐츠 배수
```

| 시나리오 | 외국인 예상 | 인사이트 |
|----------|-------------|----------|
| K콘텐츠 미연계 | 기본 (예: 97명) | baseline |
| K콘텐츠 연계 | 배수 적용 (예: 310명) | **+219% — "이래서 연계하라"** |

- 연계 요소: 인근 드라마 촬영지, K팝/한류 성지, 한류스타, 다국어 홍보
- 데이터 근거: 한국관광공사 방한 외래관광객 통계 / TourAPI 외국어 관광정보
- 심사 어필: "예산 얼마 더 써서 K콘텐츠 붙이면 외국인 +N명" → **ROI가 숫자로 보인다**

## 4. y(타깃) 확보 전략 — 가장 큰 위험, 가장 큰 기회

문제: 관광데이터랩은 **지역/시기 단위**라 "이 축제에 몇 명"이 직접 안 나온다.

해결(프록시): **증분 방문자(Incremental Visitors)**
```
축제 흥행도 프록시 = (축제 기간 지역 방문자수) − (평시 baseline 방문자수)
```
- baseline = 전년 동기 또는 축제 없는 인접 주간의 평균
- 이 "상승분"을 y로 삼아 회귀 → 순수 축제 효과를 근사
- 한계와 가정을 문서에 명시 → 심사에서 **데이터 엄밀성**으로 오히려 가점

## 5. 모델 로드맵

| 단계 | 지금 | 다음 |
|------|------|------|
| 흥행도 점수 | 규칙 기반 가중합 (`scoring.py`) | 실데이터 회귀(XGBoost/LightGBM)로 가중치 학습 |
| 방문자수 | 인구·규모 기반 추정 | 증분 방문자 y 회귀 |
| 피드백 | what-if 규칙 | 모델 민감도 기반 자동 처방 |

> 규칙 기반으로 **먼저 동작하는 데모**를 만들고, 데이터가 쌓이면 학습 모델로 교체.
> (심사에선 "동작함" > "이론상 정확함")
